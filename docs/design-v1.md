# 随手记 V1.0 实现设计

## 目标

完成 PRD 中第一版的可用闭环，让用户在 Ubuntu 上通过图形界面完成选择大类、记账、查询、编辑、删除、统计、预算和重启后继续使用。仓颉 1.0.5 工程保留为业务核心，数据保存到真实本地文件。

## 方案选择

本轮比较了三种方案：

1. 纯仓颉命令行。实现最快，但无法满足图形界面和可试用检查的要求。
2. 仓颉业务核心加 Ubuntu Tk 图形界面。仓颉实现模型、校验、统计、持久化和命令协议，Python Tk 只负责桌面交互。这个方案依赖少、能在当前环境真实验证，推荐采用。
3. 仓颉直接绑定 Qt 或其他跨平台 UI。理论上更接近最终客户端，但当前 Cangjie 1.0.5 工程没有已验证的 UI 依赖和跨平台打包链，风险会集中在工具链而不是业务闭环。

本轮采用方案 2。README 会明确记录 Ubuntu 图形验证范围，以及 Windows、Android、iOS 尚未打包验证的差异。

## 目标与边界

- 目标：覆盖 PRD F01-F08 的核心单用户离线流程。
- 目标：按 PPT 要求拆分 model、service、storage、utils，提供可解释的 Git 历史、测试和 README。
- 不做：登录、注册、云同步、收入和转账、分类删除。
- 不做：把示例数据导入正式账本。

## 结构

- `src/model/`：账单、分类、预算和统计数据结构。
- `src/utils/`：金额分解析、日期校验、文本转义、标识生成。
- `src/storage/`：版本化的本地 TSV 存储和原子替换写入。
- `src/service/`：记账、分类、预算和统计业务规则。
- `src/main.cj`：命令协议入口，输出稳定的记录格式供 GUI 使用。
- `gui/app.py`：Ubuntu Tk 图形界面，不保存业务状态，所有写操作通过仓颉程序完成。

## 数据与协议

金额统一以整数分保存。存储文件为 `data/ledger.tsv`，首行是 `schemaVersion`，记录包含分类、账单和预算。仓颉命令入口支持初始化、读取快照、增改删账单、增改分类和设置预算。自由文本使用转义后的字段保存，避免备注中的制表符和换行破坏记录。

## 验证

- Cangjie 单元测试覆盖正常金额、边界金额、非法输入和预算超支。
- `./dev.sh check` 验证版本、依赖、编译、业务测试和命令入口。
- `./dev.sh gui` 启动 Ubuntu 图形界面，手工检查核心流程和关闭重开后的数据保留。

# Ledger V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build the first usable offline ledger version with a Cangjie 1.0.5 business core, real local persistence, Ubuntu GUI trial surface, tests, README evidence, and a GitHub-ready history.

**Architecture:** Keep all business rules in the Cangjie project. Split model, utility, storage, and service packages; expose a small tabular command protocol from `main.cj`. Use a Python Tk GUI only as the Ubuntu verification surface and route every mutation through the Cangjie executable.

**Tech Stack:** Cangjie 1.0.5, CJPM, `std.fs`, `std.io`, Cangjie unit test macros, Python 3 Tkinter from the Ubuntu environment, GitHub remote `origin`.

**Spec:** `PRD.md`, `docs/ui-design-v1.md`, `docs/design-v1.md`, and the course deck `/home/zhangxxx/下载/第二次培训.pptx` (slides 41, 43, 47, 48).

## Global Constraints

- Cangjie 1.0.5 remains the business implementation language and `cjpm.toml` remains the build entry.
- Amounts use integer cents and dates use local `YYYY-MM-DD` strings.
- Adding an expense selects a category before entering amount; note is optional and is not a structured subcategory.
- No login, registration, cloud sync, income, transfer, or category deletion in V1.
- Local write failures must not report success; storage reads must not silently erase damaged data.
- The first verified GUI platform is Ubuntu; Windows, Android, and iOS remain explicitly unverified follow-up targets.
- The repository must contain at least four meaningful commits and at least three normal/boundary/error tests.

## Review Focus

- Three-decimal, zero, negative, or non-numeric amounts are rejected with text; tests live in `src/utils/money_test.cj`.
- A budget with spending above the limit reports absolute overspending and a capped progress ratio; tests live in `src/service/ledger_service_test.cj`.
- A duplicate category name is rejected without disconnecting existing expenses; tests live in `src/service/ledger_service_test.cj`.
- A write/read failure preserves the previous storage file and returns an error; tests live in `src/storage/storage_test.cj`.
- Restarting the GUI reloads the same ledger data from disk; manual verification is documented in README.

Runtime startup compatibility backport, 2026-11-10

This test distribution contains a locally modified copy of the Cangjie 1.0.5
runtime DLL. It is NOT an official SDK update or a newly rebuilt upstream DLL.
The SDK installed on the development machine is unchanged.

Upstream reference:
https://github.com/cangjielanguage/cangjie_runtime/commit/d28cbe02df27c53e278d69a26d9c326ba99bffc2
File: runtime/src/os/Windows/WinModuleManager.cpp

Upstream changed initial module enumeration to call ReadWinModuleAtRunning(),
which enumerates modules using documented Windows APIs. The former PEB walk
can read a UNICODE_STRING length header as a pointer on recent Windows builds;
the observed invalid pointer in our Windows trace is 0x620026.

This package makes the same startup routing change within the known 1.0.5 DLL:
WinModuleManager::Init()'s existing tail-call is redirected from the legacy
ReadWinModuleAtInit() routine to the already-present ReadWinModuleAtRunning().
The second upstream change is also applied: ReadModuleInfo passes the module
basename rather than its full path to WinModule. This is required for exact
runtime name lookup and correct stack frame classification. Both libc++ short
and heap string argument branches select the basename. Five file bytes differ
in total. Exports, ABI, imports, section layout, and unwind records remain
unchanged. This does not change Windows system DLLs.
